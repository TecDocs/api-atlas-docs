## 🧱 Diagnosing Structured Data Issues: JSON & YAML

<p>
After learning to interpret common <HoverExplain word="HTTP status codes" definition="Three-digit responses from a server that indicate the outcome of an HTTP request (e.g., 200 OK, 404 Not Found, 500 Internal Server Error)." />, you're now ready to uncover what often causes them: broken or misaligned structured data. Formats like <HoverExplain word="JSON (JavaScript Object Notation)" definition="A lightweight data-interchange format used for transmitting structured data." /> and <HoverExplain word="YAML (YAML Ain’t Markup Language)" definition="A human-readable data serialization format often used for configuration files." /> are the backbone of nearly every modern API interaction.
</p>

<p>
Think of <strong>JSON</strong> as a strict spreadsheet: exact, reliable, unforgiving. Every key, comma, and bracket matters. One character off, and the whole structure collapses. Now picture <strong>YAML</strong> as a screenplay: elegant, indented, and prone to being misunderstood if your spacing is off. It trades rigid syntax for readability but demands spatial awareness.
</p>

<p>
When an API request fails, it’s easy to blame the server. But more often, the problem lies in malformed data, improper nesting, or a silent schema mismatch. This section walks you through real-world examples of each failure mode and teaches you how to fix them before they snowball into more complex production issues.
</p>

<p>
Each component below displays a common bug scenario, split into a <strong>broken version (left)</strong> and a <strong>corrected version (right)</strong>. The goal is to train your eye to spot subtle issues. Each example is followed by an explanation, relevant tools, and how the issue could trigger a corresponding HTTP error.
</p>

---

## 🧾 Section 1: Debugging Syntax, Broken Brackets, Trailing Commas


<p>
In JSON, structure is everything. One forgotten comma or extra bracket breaks the parser. These issues often throw <code>400 Bad Request</code> errors or cause specs to silently fail in <HoverExplain word="Swagger UI" definition="A visual interface for testing and exploring APIs defined by OpenAPI specs." />.
</p>

<p>
In this example, we’re debugging <strong>raw JSON syntax</strong>. We simulate a malformed API payload where a missing comma results in an unparseable object.
</p>

<JSONandYAML type="json" />
<p><em>Figure 1. Debugging syntax: Notice the broken bracket and comma placement (left). Correcting this ensures API interpreters can process the payload properly (right).</em></p>

<p>
Tools like <HoverExplain word="Prettier" definition="A code formatter that can automatically fix minor JSON formatting issues." /> and <HoverExplain word="JSONLint" definition="An online tool for validating JSON structure." /> help with automated cleanup—but real understanding prevents deeper issues.
</p>

## 📄 Section 2: Debugging Structure, Indentation, Nesting Errors in YAML

<p>
YAML’s beauty is its readability, but its curse is ambiguity. A space in the wrong place changes scope, keys, or nullifies an entire block. When configuring tools like <HoverExplain word="GitHub Actions" definition="Automated CI/CD pipelines defined using YAML syntax." /> or <HoverExplain word="Kubernetes manifests" definition="YAML files used to define container-based infrastructure." />, this can trigger silent config errors.
</p>

<p>
This example illustrates an invalid environment block caused by incorrect nesting under the job definition:
</p>

<JSONandYAML type="yaml" />
<p><em>Figure 2. Debugging structure: Bad indentation (left) flattens nested values or causes YAML parsers to fail. Proper alignment (right) restores configuration logic.</em></p>

<p>
Always use a visible whitespace editor, enable linting plugins, and test your YAML using <HoverExplain word="yamllint" definition="A linter for checking syntax and structure in YAML files." /> before deployment.
</p>

## ⚙️ Section 3: Debugging Semantics, Schema Mismatches in JSON Payloads

<p>
Now, we shift to semantic debugging. The syntax may be valid—but your request still fails. Why? Because it doesn’t match the expected <HoverExplain word="OpenAPI schema" definition="A contract that defines the expected format, types, and fields in API requests and responses." />.
</p>

<p>
In this example, the payload is missing a required field and contains a value type mismatch, causing a <code>400 Bad Request</code> even though the structure is technically correct.
</p>

<JSONandYAML type="schema" />
<p><em>Figure 3. Debugging semantics: The left version passes formatting checks but fails schema validation due to a type error and a missing required field. The right version aligns with the OpenAPI contract.</em></p>

<p>
Use schema validators, Postman schema tests, or <HoverExplain word="contract testing" definition="A method of ensuring API requests and responses conform to predefined expectations." /> tools like Dredd to catch these mismatches early.
</p>
