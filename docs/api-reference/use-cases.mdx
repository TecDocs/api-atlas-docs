## 🏦 Fintech: Verifying Transactions and Nested Payloads

<p>Fintech APIs balance business agility and regulatory compliance. Payments, ledger audits, and customer data must be schema-driven and transparent to banks, vendors, and regulators. Documentation clarity avoids lawsuits and streamlines integrations.</p>

<SpotlightCode
  title="Transaction Schema (YAML & JSON)"
  yamlCode={`components:
  schemas:
    Transaction:
      type: object
      required: [id, amount, currency, method]
      properties:
        id:
          type: string
        amount:
          type: number
        currency:
          type: string
        method:
          enum: ['card', 'bank', 'crypto']
        metadata:
          type: object
          properties:
            campaign_id:
              type: string
            partner_source:
              type: string`}
  jsonCode={`{
  "components": {
    "schemas": {
      "Transaction": {
        "type": "object",
        "required": ["id", "amount", "currency", "method"],
        "properties": {
          "id": { "type": "string" },
          "amount": { "type": "number" },
          "currency": { "type": "string" },
          "method": { "enum": ["card", "bank", "crypto"] },
          "metadata": {
            "type": "object",
            "properties": {
              "campaign_id": { "type": "string" },
              "partner_source": { "type": "string" }
            }
          }
        }
      }
    }
  }
}`}
/>

<p><strong>Figure 1.</strong> This transaction schema includes optional metadata fields that only certain partners use. These become critical during campaign reporting or fraud audits, useful to finance leads and devs alike.</p>

## 🏥 Health Tech: Patient Records and Conditional Fields

<p>Healthcare APIs frequently involve optional or conditionally required fields based on patient geography, insurance, or treatment history. These conditions are difficult to understand from Swagger alone. Redoc lets compliance officers explore these constraints structurally.</p>



<RedocEmbed url="/api-atlas-docs/use-case-snapshot.yaml" />

<motion.div initial={{ opacity: 0, y: 30 }} whileInView={{ opacity: 1, y: 0 }} transition={{ duration: 0.5 }}>
Unlike Swagger, which excels at interaction, Redoc is invaluable for **understanding use case-specific schemas at a glance**. It’s ideal for:

- Reviewing complex schema structures like nested stops, role maps, or conditional fields;
- Walking through what data a system actually expects or returns in production;
- Helping cross-functional teams—legal, support, PMs, and QA—understand the contract in context.

Whether it’s healthcare coverage, token behavior, or logistics stops, Redoc snapshots act as **source-of-truth documentation** for how an API is actually used in the real world.
</motion.div>

## 🚚 Logistics & Fulfillment: Route Planning with Arrays

<p>Delivery APIs like Uber, Instacart, or FedEx often deal with nested stops, ETAs, and dependency chains. Swagger can send sample calls, but only Redoc reveals field logic for dispatch algorithms and scheduling tools.</p>

<SpotlightCode
  title="RoutePlan Schema"
  yamlCode={`components:
  schemas:
    RoutePlan:
      type: object
      required: [origin, stops]
      properties:
        origin:
          type: string
        stops:
          type: array
          items:
            type: object
            properties:
              address:
                type: string
              expected_arrival:
                type: string
                format: date-time`}
  jsonCode={`{
  "components": {
    "schemas": {
      "RoutePlan": {
        "type": "object",
        "required": ["origin", "stops"],
        "properties": {
          "origin": { "type": "string" },
          "stops": {
            "type": "array",
            "items": {
              "type": "object",
              "properties": {
                "address": { "type": "string" },
                "expected_arrival": { "type": "string", "format": "date-time" }
              }
            }
          }
        }
      }
    }
  }
}`}
/>

<p><strong>Figure 3.</strong> Stops appear as array items with nested subfields. This allows scheduling dashboards to reuse schemas across apps and services powering automation downstream.</p>

## 🧪 Developer Experience: Auth Tokens

<p>Nothing breaks onboarding like an undocumented auth response. Developers need to know what they’ll receive after login, including when tokens expire, what scopes they grant, and how long sessions persist.</p>

<SpotlightCode
  title="Token Response Schema"
  yamlCode={`components:
  schemas:
    AuthToken:
      type: object
      properties:
        token:
          type: string
        expires_in:
          type: integer
        scope:
          type: string`}
  jsonCode={`{
  "components": {
    "schemas": {
      "AuthToken": {
        "type": "object",
        "properties": {
          "token": { "type": "string" },
          "expires_in": { "type": "integer" },
          "scope": { "type": "string" }
        }
      }
    }
  }
}`}
/>

<p><strong>Figure 4.</strong> Even a simple token structure needs full clarity. Without knowing token TTL, developers may cache expired data or request new tokens too frequently. This is where Redoc shines.</p>
