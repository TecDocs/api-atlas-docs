# 📘 YAML and JSON Explained

<motion.div initial={{ opacity: 0, y: 30 }} whileInView={{ opacity: 1, y: 0 }} transition={{ duration: 0.6 }}>
<p>
In <HoverExplain word="Quickstart" definition="Our first setup section where you learned to test an API call end-to-end." /> and <HoverExplain word="Test Your First Endpoint" definition="You learned how to perform GET and POST operations, send headers, and parse JSON responses." />, we touched on how APIs communicate. But what governs the <em>structure</em> of those APIs? That story begins with <HoverExplain word="YAML" definition="A readable configuration language used to describe API structure, behaviors, and metadata." />, a quiet powerhouse behind OpenAPI.
</p>
</motion.div>

<motion.div initial={{ opacity: 0, y: 30 }} whileInView={{ opacity: 1, y: 0 }} transition={{ duration: 0.6 }}>
<p>
YAML defines endpoints, request bodies, headers, auth flows, and response types. It’s intuitive and readable, but more importantly, it’s <strong>convertible</strong> to JSON, the default response format of APIs. The distinction between the two shapes how APIs are written, consumed, and validated.
</p>
</motion.div>

## ✍️ YAML Fundamentals

<motion.div initial={{ opacity: 0, y: 20 }} whileInView={{ opacity: 1, y: 0 }} transition={{ duration: 0.6 }}>
<ul>
  <li><HoverExplain word="Indentation" definition="Indentation denotes hierarchy. Always use 2 spaces—tabs break YAML." /></li>
  <li><HoverExplain word="Scalars" definition="Simple values like strings, integers, or booleans." /></li>
  <li><HoverExplain word="Mappings" definition="Key-value structures like user: 'John'. Most YAML elements are mappings." /></li>
  <li><HoverExplain word="Sequences" definition="Dash-prefixed lists that become arrays in JSON." /></li>
  <li><HoverExplain word="Anchors" definition="Advanced YAML feature allowing you to reuse blocks of config with aliases." /></li>
</ul>
</motion.div>

<p>
These fundamentals map directly to how APIs are structured. Once you understand these YAML patterns, you’ll start recognizing them inside every OpenAPI spec, no matter the tool you use.
</p>
