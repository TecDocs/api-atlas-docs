# 🧪 Demo API

## 🔍 Why Simulate APIs Without Backend Code?

<motion.div initial={{ opacity: 0, y: 40 }} whileInView={{ opacity: 1, y: 0 }} transition={{ duration: 0.6 }}>
Not every API workflow begins with a functioning backend. In fast-paced development cycles, it's often smarter to build and test API calls **before** backend services are available. This is the core of <strong>mock-first development</strong>.

This section introduces three essential tools for simulation and testing: <HoverExplain word="Postman" definition="A GUI client for sending HTTP requests to APIs and inspecting the results." />, <HoverExplain word="Swagger UI" definition="An interactive, browser-based API explorer that reads from OpenAPI specs." />, and <HoverExplain word="Redoc" definition="A scrollable, human-readable OpenAPI viewer perfect for docs and team handoffs." />.

If you've completed the <Link to="/docs/welcome/quickstart">Quickstart Checklist</Link> and your <Link to="/docs/getting-started/requirements">environment is properly set up</Link>, you’re ready to explore your fake API spec in action, no backend required.
</motion.div>

## 📮 Postman Walkthrough (GET & POST)

<PostmanGifGallery />

<motion.div initial={{ opacity: 0, y: 20 }} whileInView={{ opacity: 1, y: 0 }} transition={{ duration: 0.5 }}>
In the first frame, we set up the HTTP environment, which is necessary to interact with endpoints via HTTP calls like <strong>"Put"</strong> or <strong>"Get"</strong>.

Then, a <code>GET /users</code> call returns mock user data, letting us verify headers, query params, and status codes. The next frame shows a <code>POST /users</code> call with a full JSON body and auth headers.

Postman highlights spec mismatches, missing fields, and helps you test different edge cases, even if your backend isn’t finished yet.

<motion.div initial={{ opacity: 0, y: 20 }} whileInView={{ opacity: 1, y: 0 }} transition={{ duration: 0.5 }}>
Swagger UI reads your <code>openapi.yaml</code> and turns it into a live, testable interface. You can expand each endpoint, view its required parameters, and send actual requests directly from the browser.

It’s useful for front-end teams testing endpoints, QA analysts validating schemas, and developers catching spec errors. Swagger loads from <code>http://localhost:3000</code> and helps detect 401 errors, token problems, or malformed JSON formatting.
</motion.div>

  <em>Figure 3. Redoc, Scrollable, developer-friendly API reference from OpenAPI spec</em>
</div>

<motion.div initial={{ opacity: 0, y: 20 }} whileInView={{ opacity: 1, y: 0 }} transition={{ duration: 0.5 }}>
Redoc transforms the same OpenAPI spec into a beautifully organized reference guide. Unlike Swagger or Postman, Redoc isn’t meant for interaction, it’s built for clarity and structure.

Perfect for product teams, onboarding docs, or audits, Redoc emphasizes categories, parameters, schema models, and required fields. Every endpoint becomes a clean, scrollable section, making it ideal for long-term documentation.
</motion.div>
